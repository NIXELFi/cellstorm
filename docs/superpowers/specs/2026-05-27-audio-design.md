# Cellstorm Audio — design

Add sound to the rendered Shorts. Everything that happens on screen makes a sound, and the
whole thing is melodic: the sim is honest and unscripted, so the audio layer is built to make
*any* event ordering sound like music rather than noise.

## The constraint that shapes the design

The renderer is **wall-clock-decoupled** — it steps the sim and screenshots, no real time passes
(`apps/renderer/src/renderBattle.ts`). So audio cannot be played live during capture. It must be a
**separate audio track generated from the event log** (which carries a `tick` on every event) and
**muxed into the MP4 by ffmpeg**. This is the "phase 2 audio" CLAUDE.md anticipated; the event log
already carries the timestamps it needs.

Audio is a pure **consumer** of the battle log. It never touches the sim and cannot perturb
gameplay or scoring — the determinism contract is preserved by construction.

## No sample assets — pure synthesis

Audio is synthesized procedurally in TypeScript (oscillators + analytic envelopes → PCM → WAV).
Rationale: stays deterministic, ships no binary/licensed assets, fits the project's code-rendered
ethos, and — crucially — the **same pure synth runs in Node** (for the ffmpeg mux) **and in the
browser** (for live preview while tuning), so preview == final (WYSIWYG), the same invariant the
visuals already hold.

Determinism: synthesis is a pure function of the `BattleLog`. Any randomness uses a local
`mulberry32` seeded from `config.seed ^ AUDIO_SALT` — a third RNG stream, disjoint from gameplay
and cosmetics.

## New package: `@cellstorm/audio`

Depends only on `@cellstorm/sim` types. No DOM, no Pixi, no Node-only imports (same purity rule as
`sim`), so it runs in Node, the browser, and vitest unchanged.

```
packages/audio/src/
  music.ts   — key/tempo/scale from seed; per-team voice (chord tone, timbre, pan)
  score.ts   — buildAudioScore(log): BattleLog -> AudioScore (timed notes, seconds)
  synth.ts   — renderScore(score, sampleRate): stereo Float32 PCM (pure)
  wav.ts     — pcmToWav(left, right, sampleRate): Uint8Array (16-bit PCM WAV)
  index.ts   — public surface + renderBattleAudioWav(log, fps, sampleRate) convenience
  types.ts   — AudioScore, Note, Voice, Timbre
```

### `music.ts` — always-consonant by construction

- **Key + tempo from seed.** Root pitch class and mode (major/minor **pentatonic**) chosen from
  `config.seed`; tempo (BPM) chosen in a tasteful range (~96–132). Pentatonic means no avoid-notes:
  any combination of scale degrees is consonant.
- **Per-team voice.** Each team (≤6) is assigned, deterministically from its index + power:
  - a **chord tone** (root / 2nd / 3rd / 5th / 6th of the pentatonic) so teams harmonize with
    each other;
  - a **timbre** derived from the power's archetype shape (`glyphs.ts`): square=tanky→square-ish
    (hollow, gritty), triangle=aggressive→saw-ish (bright), diamond=burst→bell/FM-ish,
    hexagon=control→pulse, circle=sustain→sine/triangle (soft);
  - a **stereo pan** baseline (spread across the field), nudged per-event by the event's x.

### `score.ts` — event → music mapping

`tick → seconds = tick / fps`. Maps each `SimEvent` to zero or more `Note`s:

- **death** — the signature element. A plucked note at the dying team's chord tone; the **octave
  rises as the battle approaches its climax** (`tick / durationTicks`), so the cumulative death
  sequence is an ascending melodic run that peaks at the end — "deaths play out a song." Always in
  key (pentatonic + chord tone). Panned by `x`. Velocity has a small deterministic jitter.
- **explosion** (Bomb) — low sub boom (root, −2 oct) with a fast downward pitch drop + a short
  filtered-noise transient; longer decay. Punctuation.
- **projectileFire** (Sniper) — a quick, quiet high "pew": short descending sine sweep.
- **leadChange** — a bright two-note rising bell motif (up a 4th/5th in key); the momentum/drama cue.
- **battleEnd** — winner sting: an ascending arpeggio of the winner team's chord resolving to the
  tonic, over a short sustained pad. Triumphant.
- **musical bed** (so even lulls are melodic) — a continuous arpeggiated bassline + a soft beat
  pulse, in key at the seed tempo, spanning the whole video. Its **intensity (amplitude + low-pass
  cutoff) is modulated by on-screen action density** (a deaths-per-second envelope derived from the
  log's death ticks), so the music swells toward the climax and the win. Generated by `score.ts`
  as scheduled bed notes, not a special-case in the synth.

### `synth.ts` — pure rendering

Mix every `Note` into a stereo `Float32Array` pair. Each note: oscillator (waveform per timbre,
built from a small harmonic series for square/saw to stay alias-light), analytic ADSR-ish envelope
(fast attack, exponential decay for plucks; sustain for pad), gain, equal-power pan. One-pole
low-pass for the bed swell. Master soft-clip (`tanh`) + normalize to avoid clipping when many
notes stack. Mono-summing safe (phones). Deterministic: no `Math.random`.

### `wav.ts`

Standard 44-byte PCM WAV header + interleaved 16-bit little-endian stereo samples. Returns
`Uint8Array` (works in Node `writeFile` and browser `Blob`/`decodeAudioData`).

## Renderer integration (the shipped artifact)

`apps/renderer/src/cli.ts`:
1. After resolving the config, call `runBattle(config)` to get the `log` (deterministic; matches
   the browser stepping per the determinism contract — cheap next to Playwright).
2. `renderBattleAudioWav(log, fps)` → write `audio.wav` into the temp frames dir.
3. `encode()` muxes it. `ffmpegArgs(framesDir, fps, outPath, audioPath?)` gains an optional audio
   input: `-i audio.wav -c:a aac -b:a 192k -shortest` when present (kept a pure function, still
   unit-tested). `-shortest` aligns the track to the (frame-count-bound) video.
4. A `--mute` flag skips audio (silent render).

## Harness preview (tuning)

`apps/harness` gets a **"Sound" toggle**. When on and playback runs at 1× from tick 0, the harness
synthesizes the same `AudioScore` to an `AudioBuffer` (via the shared pure synth → `Float32Array`)
and plays it through Web Audio, started in lockstep with playback. Disabled while scrubbing or at
speed ≠ 1 (keeps sync trivial; the real fidelity check is the rendered MP4). Respects browser
autoplay policy (starts on a user gesture — the existing play button).

## Testing

Pure functions, TDD:
- `music`: same seed → same key/tempo/voices; voices distinct per team; chord tones in-scale.
- `score`: deterministic (same log → byte-identical score); death octaves rise with progress;
  every event type produces the expected notes; bed spans `[0, totalTicks/fps]`.
- `synth`: deterministic PCM; output bounded in [-1, 1]; silence in → silence out; length matches
  score end.
- `wav`: header fields correct; round-trips sample count.
- `encode`: `ffmpegArgs` includes the audio input + codec flags iff an audio path is given
  (existing video-only behavior unchanged when omitted).

Verification beyond unit tests: render one real MP4 and confirm with `ffprobe` that it carries an
AAC audio stream of the expected duration.

## Out of scope (YAGNI)

- Sample-based instruments / external audio assets.
- Music-theory beyond pentatonic + chord tones.
- Per-event live audio in the harness at variable speed / while scrubbing.
- A resolution/quality audio toggle in the UI beyond on/off.
